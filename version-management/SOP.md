# AMC 原型与版本管理 SOP

## 1. 适用范围

适用于 Amazon Marketing Cloud 报告系统（AMC Reports / AMC Hub）的原型设计、版本管理、公开预览、功能发布、UI 走查和上线验收。

## 2. 角色与职责

版本管理助理负责：

- 维护功能清单、版本清单和变更日志。
- 执行新增、搁置、恢复、发布、下线和回滚操作。
- 确保正式公开页面只展示当前已发布清单中开启的功能。
- 生成原型时遵循本 SOP 的 UI 规范。
- 功能上线后，基于 UI 规范执行页面走查并输出缺陷清单。

## 3. 规范来源与优先级

遇到冲突时按以下优先级执行：

1. 已确认的业务需求和交互规则。
2. 本 SOP 登记的 Figma UI 规范。
3. 当前已发布版本中的通用页面结构和组件行为。
4. 原型中的临时样式。

未在 Figma 或需求中体现的内容不得臆造；必须在备注中标记“待确认”。

## 4. 版本管理原则

1. 主干唯一：所有功能最终合入 main；发布版本由清单快照控制。
2. 搁置不等于删除：清单置 off，代码保留，可恢复。
3. 白名单展示：未在版本清单中声明或开关为 off 的功能默认不展示。
4. 正式公开首页只使用已确认的 AMC-Main 发布清单。
5. 版本快照不可覆盖；修复或范围变化必须新建快照。
6. 每项版本操作执行前必须向产品负责人确认。

## 5. 版本与功能操作

### 5.1 新增

注册 feature_key 并绑定控制点 → 开发 → 业务预览 → 确认合入 main → 默认 off → 正式预览 → 确认发布 → 置 on。

### 5.2 搁置

清单置 off → 从正式公开页面隐藏全部入口和直达路径 → 登记变更日志 → 保留代码和独立预览。

### 5.3 恢复

同步最新 main → 解决冲突 → 清单置 on → 执行功能、可见性和 UI 验收 → 发布。

### 5.4 发布

冻结代码基线和版本清单快照 → 更新正式公开页面 → 验收 → 登记版本清单和变更日志。

### 5.5 下线

冻结最后快照 → 清单置 off → 确认无恢复计划后删除代码 → 功能状态改为“已下线”。

### 5.6 回滚

- 全局问题：回滚到上一组已验收的代码基线和清单快照。
- 单一功能问题：关闭该 feature_key，并发布补丁快照。

## 6. 预览、确认与发布流程

1. 在独立预览地址生成待确认版本。
2. 预览默认直接进入 AMC Reports，不显示中间页或自动跳转过程。
3. 产品负责人确认功能、内容、交互和 UI。
4. 未确认前不得更新正式公开首页。
5. 确认后更新正式首页、三张管理表和版本快照。
6. 发布后重新执行完整验收。

## 7. UI 设计规范

### 7.1 基本原则

- 生成原型时必须优先复用 Figma 中已有组件和变量，禁止用近似样式替代已有规范。
- 同一种控件在不同页面必须保持尺寸、字体、圆角、颜色和状态一致。
- 颜色只用于表达层级、状态和关键操作，不得用颜色代替文字说明。
- 页面必须覆盖默认、悬停、聚焦、选中、禁用、加载、成功、警告、错误和空状态中适用的状态。
- 业务功能的显示与隐藏由版本清单控制；UI 样式不得绕过 feature_key。

### 7.2 字体与排版

中文界面以 Noto Sans SC 为主；英文与数字优先使用 Inter / Outfit。若生产环境字体不可用，必须使用视觉指标接近的系统字体并在验收记录中说明。

### 7.4 圆角与间距

| Token | 数值 | 默认用途 |
|---|---:|---|
| rounded-none | 0 px | 无圆角结构 |
| rounded-sm | 4 px | 输入框、下拉、紧凑按钮 |
| rounded | 8 px | 卡片、常规按钮、小型弹窗 |
| rounded-md | 12 px | 大卡片、内容容器 |
| rounded-lg | 16 px | 大型弹窗或重点容器 |
| rounded-xl | 24 px | 特殊大圆角容器 |
| rounded-full | 9999 px | 状态胶囊、圆形按钮 |

### 7.5 组件规范

#### 按钮

- 层级：Primary / Secondary / Tertiary / Quaternary / Link / Icon / Floating。
- 状态：Default / Hover / Active / Disabled；危险操作增加 Warning 或 Danger 状态。
- 同一区域只能有一个主按钮。
- 图标按钮必须提供 tooltip 或 aria-label。
- 禁用按钮必须可识别，且不能仅靠颜色表达禁用原因；必要时提供提示。

#### 输入框、搜索和下拉

- 状态：Normal / Focus / Filled / Success / Error / Disabled。
- 支持前后图标、清除、字数限制、帮助说明、前后附加内容。
- 必填项必须有统一标记；错误信息紧邻控件并使用 SC/body/small。
- 下拉菜单必须包含默认、选中、悬停、禁用和无数据状态。
- 多选必须明确已选项、全选逻辑和清空入口。

#### 单选、复选和开关

- 必须覆盖选中 / 未选中 × 可用 / 禁用。
- 控件和标签整体均可点击。
- 不得仅通过颜色区分选中状态。

#### Tab 和导航

- 区分一级 Tab、二级 Tab 和产品页签。
- 激活状态使用 strong 字重和主色；关闭按钮、溢出和滚动状态按组件规范处理。
- 页面首屏不得先进入其他 Tab 后自动切换。

#### 表格

- 表头使用 SC/label/medium，内容使用 SC/body/medium。
- 表头背景、边框、行悬停、选中、空状态、加载、分页、固定列和溢出必须统一。
- 数字列右对齐；文本列左对齐；操作列宽度和位置保持稳定。
- 长文本必须使用截断和悬停完整展示，不得破坏列宽。
- 批量操作必须与勾选状态联动，并提供选择结果提示。

#### 弹窗、抽屉和提示

- 标题使用 SC/h2；正文使用 SC/body/medium。
- 明确主次按钮；危险确认必须说明对象、数量和后果。
- Tooltip 使用统一深色背景，避免遮挡目标控件。
- Toast / Alert 必须区分 Success / Warning / Danger / Information。

#### 日期、上传与分页

- 日期选择支持单日、日期范围和日期时间，格式由业务规则统一。
- 上传覆盖待上传、上传中、成功、失败和重试。
- 分页需展示当前页、总量和翻页状态；无更多数据时禁用对应操作。

#### 图表

- 图表颜色优先使用 Figma 的“可视化图表配色规范”。
- 坐标、图例和次要标注使用 SC/body/extra-small。
- 图例、tooltip、空数据、加载和异常状态必须设计。
- 颜色数量不足时按既有调色板顺序扩展，不得临时随机取色。
- 图表信息不得仅依赖颜色；必要时增加形状、线型或文字。

### 7.6 响应式与滚动

- 默认验收视口：1440 × 900；兼容视口：1920 × 1080、1366 × 768。若业务另有支持矩阵，以业务矩阵为准。
- 页面顶部、侧边导航、表头、固定列和操作列不得互相遮挡。
- 左右分栏需要独立滚动时，必须保持标题和关键操作可见。
- 弹窗不得超出视口；小视口下应限制高度并允许内容区滚动。

### 7.7 可访问性

- 可交互元素必须具备可识别名称。
- 键盘可访问，焦点顺序与视觉顺序一致。
- Focus 状态清晰可见。
- 状态、错误和必填信息不得仅使用颜色传递。
- 图标按钮、图表和图片必须提供 aria-label、替代文本或等价说明。

## 8. 基于 UI 规范生成原型

1. 明确页面、业务场景、功能状态和目标版本。
2. 从 Figma 规范中选择对应组件、字体和 token。
3. 建立页面结构：导航 → 面包屑 → 页面标题 / 操作区 → 筛选区 → 内容区 → 反馈层。
4. 补齐适用的控件状态和异常场景。
5. 将功能绑定到 feature_key，未声明功能默认隐藏。
6. 生成独立公开预览链接，默认直接进入目标主页。
7. 按第 10 节检查清单自检。
8. 产品负责人确认后才能发布。

## 9. 上线后 UI 验收流程

### 9.1 输入

- 待验收系统地址。
- 账号和角色范围。
- 对应需求、Figma 页面或组件。
- 发布版本、环境和 feature_key 清单。
- 业务支持的浏览器与分辨率。

### 9.2 Browser Use / TinyFish 走查

工具使用规则：

- 公开原型和无需登录的页面，可使用内置 Browser Use 直接走查。
- 需要登录态、跨页面连续操作、保存浏览器会话或系统后台验收时，优先使用 TinyFish。
- 登录凭据应通过已连接的安全登录方式或凭据库处理，不得在聊天、截图或验收记录中明文展示。
- TinyFish 仅用于用户明确授权的系统和账号范围，不得扩大验收对象。

1. 打开指定环境并记录最终 URL、版本、浏览器和视口。
2. 按导航逐页走查，不跳过入口、Tab、按钮、弹窗、筛选、表格、下载和异常状态。
3. 对照 Figma 检查布局、字体、颜色、间距、圆角、图标、控件状态和文案。
4. 检查不同角色、不同数据状态和 feature_key 的可见性。
5. 在关键节点保留截图证据。
6. 输出问题清单并复验修复结果。

涉及登录、验证码、敏感信息或对外提交时，必须在操作前请求用户确认；不得在验收记录中暴露密码、Token 或个人敏感信息。

### 9.3 缺陷分级

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 | 阻断核心任务或存在严重安全问题 | 无法进入页面、数据越权、核心操作不可用 |
| P1 | 主要流程错误或版本可见性错误 | 搁置功能对外可见、主要按钮不可用、严重遮挡 |
| P2 | 明显偏离 UI 规范但不阻断流程 | 字号、间距、颜色、组件状态明显不一致 |
| P3 | 轻微视觉或文案问题 | 个别对齐、截断、提示文案不统一 |

### 9.4 UI 缺陷记录字段

| 字段 | 内容 |
|---|---|
| 页面 / URL | 问题所在页面及可复现地址 |
| 版本 / 环境 | tag、清单快照、测试或生产环境 |
| 账号角色 | 仅记录角色，不记录密码 |
| 视口 / 浏览器 | 分辨率、浏览器和版本 |
| 缺陷级别 | P0 / P1 / P2 / P3 |
| 实际结果 | 当前页面表现 |
| 预期结果 | Figma 或 SOP 对应规范 |
| 证据 | 截图、录屏或控制台信息 |
| 复现步骤 | 最短可复现路径 |
| 状态 | 待修复 / 待复验 / 已通过 |
| 负责人 | 修复责任人 |
| 备注 | 特殊说明 |

## 10. 发布与 UI 联合验收清单

- [ ] 正式页面默认直接进入 AMC Reports，无中间页闪现或自动切换。
- [ ] on 功能全部可见且可进入；off 功能入口、直链和数据调用均不可用。
- [ ] 版本清单与页面实际展示一致。
- [ ] 字体、字号、行高和字重符合规范。
- [ ] 颜色、边框、背景和状态色符合 token。
- [ ] 间距、圆角、对齐和滚动符合规范。
- [ ] 按钮、输入、下拉、单选、复选、Tab 状态完整。
- [ ] 表格字段、固定列、空状态、加载和分页符合规范。
- [ ] 弹窗、提示、错误和危险操作符合规范。
- [ ] 图表颜色、图例、坐标、tooltip 和空状态符合规范。
- [ ] 1440 × 900、1920 × 1080、1366 × 768 关键页面无严重遮挡。
- [ ] 键盘焦点、可访问名称和非颜色状态表达通过。
- [ ] 关键页面已截图留证。
- [ ] 功能清单、版本清单和变更日志已更新。
- [ ] 版本快照已固化。

## 11. 日常维护

- Figma 源文件更新时，重新解析 token、组件和有效页面，并更新本 SOP。
- 每次原型新增组件时，先确认是否已有 Figma 组件；不得重复造轮子。
- 每次上线验收后，将缺陷清单和复验结果归档到对应版本。
- 仅输出本次发生变化的表格行或验收清单；仓库内维护完整记录。
